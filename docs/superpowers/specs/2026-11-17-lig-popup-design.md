# Lig, the IDE-style completion popup

**Status:** approved by the owner on 2026-11-17, after a spike in their regular shell.

## Why

The research ([`../research/2026-11-17-shell-ux-options.md`](../research/2026-11-17-shell-ux-options.md)) put
[Lig](https://github.com/KevenGoncalves/lig) in the Try tier: an IDE-style popup under the cursor, the successor to
Fig (it reads Fig's spec format and ships Fig's specs for 789 commands). fzf-tab can only be restyled; it stays a
full-width picker. The owner tried Lig on 2026-11-17 and wants it: `todo`, `dots theme`, `cd` and `git checkout`
all completed in the popup.

The spike also found a bug in our own code: the warning-colour hook returned 1 on every line that was not risky,
and `add-zle-hook-widget` stops at the first failing widget, so p10k's and Lig's redraw hooks never ran. That is
fixed (`2e96ba3`) and not part of this work.

## Goals

- Lig's popup in every interactive zsh on a desktop, macOS and Linux.
- Commands without a Fig spec complete through zsh's own completion (`completers = ["shell"]`): `todo` through
  `_todo`, the `config/bin` scripts through their usage completions.
- Lig's colours follow `dots theme`, switching live in open tabs.
- The repository owns the configuration: no hand-made `~/.config/lig`.

## Non-goals

- Bash, fish or nushell integration (zsh is the shell here; bash keeps fzf and gomi only).
- Containers: the images stay as they are (Lig is a desktop tool; CST unchanged).
- Removing fzf-tab, or changing its look.
- Lig's own history (Ctrl-R) or package search.

## Anti-goals

- **No process at startup** beyond what Lig needs to run (the anti-goal of the theme design): the shell must not
  run `lig init` on every start.
- **No dead Tab:** where Lig has nothing to offer, Tab still opens fzf-tab.
- **A shell without Lig** (not installed, `LIG_DISABLE=1`, no terminal, `zsh -c`) behaves exactly as today.

## Decisions (owner, 2026-11-17)

| Topic | Decision |
| --- | --- |
| fzf-tab | Stays as the fallback: Tab once the popup is closed or empty (Lig's documented behaviour). |
| Ctrl-R | Back to fzf's history widget: `[behavior] history = false` (Lig then leaves Ctrl-R to the shell). |
| Online search | Off: `[behavior] online = false`. |
| Theme | Each theme folder gets a `lig.toml`; `dots theme` switches it. |
| Where | Desktop profile only (the Brewfile's desktop section); containers unchanged. |

## Design

### Install

`brew "kevengoncalves/tap/lig", trusted: true` in the Brewfile's desktop formulae (no `tap` line, per the
Brewfile's header). The brewfile-profiles spec gains Lig in desktop and not in container.

### Configuration: one file per theme, one link

Lig reads only `~/.config/lig/config.toml`, has no include, and applies a changed `theme` or `[colors]` to open
tabs. So the active theme supplies the whole file, as Ghostty's `auto` link does:

- `config/theme/themes/<name>/lig.toml`: the full Lig config, the same in every theme except `[ui]` and `[colors]`.
- `config/lig/config.toml`: a committed relative symlink to the state link,
  `${XDG_STATE_HOME:-~/.local/state}/dots/theme/current/lig.toml`, the same depth trick as `config/ghostty/auto`
  (`b076455`).
- `dotfiles.toml` links `~/.config/lig` to `config/lig`.
- A spec keeps the shared sections identical across themes, so a setting cannot drift between them.

The shared settings:

```toml
[behavior]
completers = ["shell"]   # commands with no Fig spec ask zsh's own completion (_todo, _dots, …)
online = false           # no package registry searches
history = false          # Ctrl-R stays fzf's
```

Each theme's `[ui] theme = "catppuccin"` plus explicit `[colors]` from its palette, so the flavour never depends
on which Catppuccin Lig's built-in is: `bg`, `fg`, `selected_bg`, `selected_fg`, `match_fg`, `description_fg`,
`selected_description_fg`, `border_fg`, `scrollbar_fg`, `info_fg`.

A missing state link leaves the config link dangling, and Lig would fall back to its defaults (no shell completer,
online search on). Bootstrap therefore creates the link when it is missing: the existing
`[bootstrap.hooks.post-dotfiles]` runs `dots theme catppuccin-mocha` when the state link does not exist.

### Shell integration without a process per start

Lig's integration is two blocks, `lig init zsh pre` (top of `.zshrc`: re-exec the shell inside `lig shell`) and
`lig init zsh post` (end: connect zle). Their output only changes with Lig's version, so the shell sources cached
copies instead of running `lig init`:

- `${XDG_CACHE_HOME:-~/.cache}/dots/lig/{pre,post}.zsh`, regenerated by a `mise run zsh:lig` inline task (usage,
  no arguments) and by the bootstrap hook above.
- `.zshrc` sources each file when it exists and `$commands[lig]` is set (a hash lookup, no process). A stale cache
  (Lig upgraded) is caught by comparing the files with `-nt` against `$commands[lig]`: when the binary is newer, the
  shell skips Lig for that start and prints one line asking for `mise run zsh:lig`. No process, no silent breakage.

The pre block keeps its own guards (interactive, a terminal, not `dumb`, not inside Emacs, `LIG_DISABLE`), so
`zsh -c`, scripts, the specs and the Docker images never enter Lig.

### What the shell gains and costs

- The pre block re-execs zsh inside Lig once per terminal, so the first shell runs `.zshenv` and the top of
  `.zshrc` twice. `zsh:bench` measures the interactive start; the cost is the owner's to accept at the checkpoint.
- `zsh:verify`'s parity snapshot runs under a terminal and so inside Lig: it gains Lig's `_lig_*` functions and
  widgets. The baseline is retaken after the owner's approval.

## Verification

- Specs: the two `lig.toml` share every section but `[ui]`/`[colors]`; the shared settings hold the three values
  above; `config/lig/config.toml` resolves to the state link's `lig.toml`; `dots theme` choices still match the
  folders; `.zshrc` runs no `lig` process (it sources cached files only); the Brewfile has Lig in desktop only.
- Gates: `mise run test:specs`, `hk check --all`, `zsh:verify` (under `script`), `zsh:bench`, and the Debian
  image build plus CST (bootstrap changes).
- Owner checkpoint, in a new Ghostty tab: `git checkout `, `todo `, `dots theme `, `cd ` pop up; Tab on a closed
  popup opens fzf-tab; Ctrl-R opens fzf; `dots theme catppuccin-macchiato` recolours the popup in the open tab.
