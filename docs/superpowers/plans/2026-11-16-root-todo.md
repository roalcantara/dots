# Root TODO.yaml Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A root `TODO.yaml` for the dots repo, driven by the `todo` CLI installed from the Brewfile (dev profile).

**Architecture:** brew bundle builds RayanBO/todo v0.2.9 from git with `cargo install` into `$CARGO_HOME/bin`; a zsh
PATH fix makes that directory reachable; the blog wrapper drops its mise pin and uses the same binary; the root list
is plain `todo` run from the repo root.

**Tech Stack:** Homebrew bundle (Brewfile `cargo` entry), zsh, mise file tasks, Bun test, hk (yamllint).

**Spec:** [`docs/superpowers/specs/2026-11-16-root-todo-design.md`](../specs/2026-11-16-root-todo-design.md)

## Global Constraints

- Branch `chore/add-todos` (already checked out). Work there; no worktree, no push, no PR.
- Every git call goes through the SOPS wrapper: `g() { git -c filter.sops.clean=cat -c filter.sops.smudge=cat "$@"; }`.
- Stage named paths only; never `git add -A` / `git add .`.
- Commits: Conventional Commits, capitalised description, ending with the line
  `Co-Authored-By: Gemini 3.8 Flash <noreply@google.com>` (the executor's own attribution).
- Tool pin: RayanBO/todo **v0.2.9**; cargo package name **`todo-cli`**, binary **`todo`**.
- Brewfile entry, verbatim: `cargo "todo-cli", source: "https://github.com/RayanBO/todo?tag=v0.2.9"`.
- `todo` only on the dev profile (`desktop,dev`), never on `container` or `desktop`.
- No mise wrapper for the root list; `mise run blog:todo` stays.
- Do not touch `docs/blog/TODO.yaml`, `config/agents/commands/wip/resume.md`, or any file not named in a task.

## Review Focus

1. **Fresh machine order:** brew bundle must reach the `cargo` entry after `brew "rust"` is installed, or the entry
   fails and bootstrap only warns. Task 1 places it right after `brew "rust"` and asserts the order in the spec.
2. **`CARGO_HOME` unset when brew bundle runs:** cargo would install into `~/.cargo/bin`, off PATH. brew keeps
   `CARGO_HOME` (it is in `bin/brew`'s pass-through list); Task 1 Step 6 checks the binary lands in
   `$CARGO_HOME/bin`.
3. **`cargo` shadowed:** `$CARGO_HOME/bin` also holds rustup proxies (`cargo`, `rust-analyzer`). Appending it after
   `$path` must leave `command -v cargo` unchanged. Task 2's spec asserts it is last.
4. **Stale mise shim:** with the `#MISE tools=` pin gone, `~/.local/share/mise/shims/todo` would still win on PATH
   until the mise install is removed. Task 3 Step 3 removes it; Step 4 checks `command -v todo`.
5. **Run from a subdirectory:** `todo` reads only `./TODO.yaml`; elsewhere it fails with
   `./TODO.md not found`. The docs line (Task 4) says "from the repo root"; nothing else handles it (by design).

### Task 2: `$CARGO_HOME/bin` on zsh's PATH

**Files:**

- Modify: `config/zsh/opt/rc.d/env.zsh:137` (inside `env::paths`)
- Create: `test/integration/bootstrap/zsh-paths.spec.ts`

**Interfaces:**

- Consumes: nothing.
- Produces: in every zsh, `$path` ends with `${CARGO_HOME:-$XDG_DATA_HOME/cargo}/bin`.

- [ ] **Step 1: Write the failing test** — a new spec. Header comment: why (cargo installs into `$CARGO_HOME/bin`).
  Helper `paths(env)` runs
  `zsh -fc 'source config/zsh/opt/rc.d/env.zsh; env::paths; print -l $path'` from the repo root with
  `env: { HOME, PATH: "/usr/bin:/bin", ...env }` and returns the lines. `describe.skipIf(!Bun.which("zsh"))`. Cases:

```ts
it("adds $CARGO_HOME/bin, not $CARGO_HOME", () => {
  const p = paths({ CARGO_HOME: "/tmp/ch", XDG_DATA_HOME: "/tmp/xdg" });
  expect(p).toContain("/tmp/ch/bin");
  expect(p).not.toContain("/tmp/ch");
});
it("falls back to $XDG_DATA_HOME/cargo/bin", () => {
  expect(paths({ XDG_DATA_HOME: "/tmp/xdg" })).toContain("/tmp/xdg/cargo/bin");
});
it("puts it last, so rustup's proxies never shadow cargo", () => {
  const p = paths({ CARGO_HOME: "/tmp/ch", XDG_DATA_HOME: "/tmp/xdg" }).filter(Boolean);
  expect(p.at(-1)).toBe("/tmp/ch/bin");
});
```

  If `CARGO_HOME` leaks from the runner's environment, delete it from the spawned env for the fallback case.
