# TUI launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open any TUI listed in `config/tuis.toml` from Raycast in a floating, centred Ghostty window on the
focused screen, closed when the tool exits; `psc` is the pilot.

**Architecture:** `yb tui <name> --command … --width … --height … [--pause]` does the window work
(Ghostty AppleScript + yabai). A Bun generator turns `config/tuis.toml` into one Raycast Script Command per
entry that calls `yb tui` with that entry's values, so `yb` never parses TOML. `--check` keeps the generated
scripts in sync, like `karabiner:build`.

**Tech Stack:** zsh + usage (`config/bin/yb`), Ghostty 1.4 AppleScript, yabai, Bun (`Bun.TOML.parse`),
bun:test, mise tasks.

**Spec:** `docs/superpowers/specs/2026-11-12-tui-launcher-design.md`

## Global Constraints

- Default window size 875×600 points; an entry's `size = [w, h]` overrides it.
- The window closes when the tool exits (`wait after command` false); no Esc binding anywhere.
- Ghostty window title (`name override`) is exactly `tui:<name>`.
- The tool runs through the user's login shell: `$SHELL -lic '<command>'` (fallback `/bin/zsh`).
- Generated scripts live in `config/raycast/scripts/tuis/<name>.sh`, `@raycast.mode silent`,
  `@raycast.packageName TUIs`, and start with the line `# Generated by mise run tuis:build from config/tuis.toml; do not edit.`
- Entry names match `^[a-z0-9][a-z0-9-]*$`.
- Use the SOPS git wrapper; stage named paths only; Conventional Commits with a capitalized description.

## Review Focus

- A command with spaces and single quotes (`bash -c 'dust; read -n 1 -s'`) reaches the shell intact — Task 1 and Task 2 tests.
- Ghostty not running: it is launched first and the TUI window still opens — Task 1 test.
- yabai missing: the window opens, no yabai calls, exit 0 — Task 1 test.
- A new window that is already floating is not toggled back to tiled — Task 1 test.
- An entry removed from `config/tuis.toml` leaves no stale Raycast script, and `--check` flags one — Task 2 test.

### Task 1: `yb tui`

**Files:**
- Modify: `config/bin/yb` (usage block near `cmd "notes"`, the skip-`-x` case list, `ghostty_window`/`follow_new_window`, main `case`)
- Test: `test/integration/bin/yb.spec.ts` (osascript stub + new `describe("tui")`)

**Interfaces:**
- Produces: `yb tui <name> --command <cmd> [--width <n>] [--height <n>] [--pause]` (defaults 875, 600). Exit 0 when the
  window was opened or focused; exit 1 with `yb tui: missing --command` when `--command` is empty.

- [ ] **Step 1: Teach the osascript stub to record TUI windows**

  In `OSASCRIPT`, before the `*"new window"*` case, add `*"tui:"*) printf 'osascript tui %s\n' "$*" >> "$YB_STUB_LOG" ;;`.

- [ ] **Step 2: Write the failing tests** in a new `describe("tui")`, display stub
  `YB_STUB_DISPLAY='{"index":1,"frame":{"x":0,"y":25,"w":1512,"h":957}}'`, new window
  `YB_STUB_WINDOWS_2='[{"id":42,"app":"Ghostty","title":"","display":1,"is-floating":false}]'`:

  - `opens the tool in a floating, centred window`: `yb(["tui","psc","--command","psc"])` → exit 0; the `osascript tui`
    call contains `command`, `-lic 'psc'`, `wait after command`, `tui:psc`; the yabai calls after the queries are exactly
    `["-m window 42 --toggle float", "-m window 42 --resize abs:875:600", "-m window 42 --move abs:318:203", "-m window --focus 42"]`.
  - `uses the given size`: `--width 1000 --height 700` → `--resize abs:1000:700`, `--move abs:256:153`.
  - `does not re-tile a window that is already floating`: `"is-floating":true` → no `--toggle float` call.
  - `brings the window to the focused screen`: new window on `"display":2` → `-m window 42 --display 1` comes before `--toggle float`.
  - `focuses the open window instead of opening another`: `YB_STUB_WINDOWS_1='[{"id":7,"app":"Ghostty","title":"tui:psc"}]'`
    → calls contain `-m window --focus 7` and no `osascript tui`.
  - `keeps quotes in the command`: `--command "bash -c 'dust; read -n 1 -s'"` → the osascript text contains
    `-lic 'bash -c '\''dust; read -n 1 -s'\'''` (shell-escaped once, then AppleScript-escaped: `\"` for any `"`).
  - `pauses before closing when asked`: `--pause` → the command text ends with `; read -k1 -s` inside the `-lic` string.
  - `launches Ghostty first when it is not running`: `GHOSTTY_RUNNING=false` → `open -a Ghostty` precedes `osascript tui`.
  - `opens without yabai`: `DOTS_YABAI` pointing at a missing file → exit 0, `osascript tui` recorded, no `-m` calls.
  - `needs a command`: `yb(["tui","psc"])` → exit 1, output contains `missing --command`.

- [ ] **Step 3: Run them to see them fail**

  Run: `bun test test/integration/bin/yb.spec.ts -t tui` — Expected: FAIL (unknown command `tui`).

- [ ] **Step 4: Implement `tui` in `config/bin/yb`**

  - Usage: `cmd "tui" help="Open a TUI in a floating Ghostty window (config/tuis.toml)"` with `arg "<name>"`,
    `flag "--command <command>"`, `flag "--width <width>" default="875"`, `flag "--height <height>" default="600"`, `flag "--pause"`.
  - Add `tui` to the case list that skips the yabai `-x` check.
  - `tui_open name command width height pause`: one `query --windows` gives both the existing `tui:<name>` window
    (focus it and return) and the `before` id list; build the shell line `${SHELL:-/bin/zsh} -lic '<command>[; read -k1 -s]'`
    (escape `'` as `'\''`, then `\` and `"` for AppleScript); if Ghostty is not running, `open -a Ghostty` and `sleep 1`;
    then one `osascript` that makes a `new surface configuration` with `command`, `wait after command` false, opens
    `new window with configuration cfg`, and sets `name override` of its focused terminal to `tui:<name>`.
  - Split the wait loop out of `follow_new_window` into `new_window app before` that prints `id display floating`
    (reuse it from `follow_new_window`). After the window appears: `--display` when needed, `--toggle float` unless
    floating, `--resize abs:W:H`, `--move abs:X:Y` with `X = frame.x + (frame.w - W) / 2`, `Y = frame.y + (frame.h - H) / 2`
    (integer division, from `query --displays --display`), then `window --focus`. Skip all yabai steps when yabai is not executable.

- [ ] **Step 5: Run the tests**

  Run: `bun test test/integration/bin/yb.spec.ts` — Expected: all pass, including the existing term/nvim tests.

- [ ] **Step 6: Commit**

  ```bash
  g add config/bin/yb test/integration/bin/yb.spec.ts
  g commit -m "feat(yb): Open a TUI in a floating Ghostty window"
  ```

### Task 2: `config/tuis.toml` and the Raycast generator

**Files:**
- Create: `config/tuis.toml`, `script/tuis-build.ts`, `config/raycast/scripts/tuis/psc.sh` (generated), `test/integration/bootstrap/tuis.spec.ts`
- Modify: `mise.toml` (task `tuis:build` next to `karabiner:build`)

**Interfaces:**
- Consumes: `yb tui` from Task 1.
- Produces: `mise run tuis:build [-- --check]`; `DOTS_TUIS_TOML` and `DOTS_TUIS_DIR` override the input file and output folder (tests).

- [ ] **Step 1: Write the failing spec** `test/integration/bootstrap/tuis.spec.ts` (temp dir via the two env vars):

  - `writes one Raycast command per entry`: toml `[psc]\ntitle = "Copy a secret"\ncommand = "psc"\nicon = "🔑"` →
    `psc.sh` equals exactly:

    ```sh
    #!/bin/zsh
    # Generated by mise run tuis:build from config/tuis.toml; do not edit.
    # @raycast.schemaVersion 1
    # @raycast.title Copy a secret
    # @raycast.mode silent
    # @raycast.packageName TUIs
    # @raycast.icon 🔑
    export PATH="/opt/homebrew/bin:/usr/bin:/bin:$PATH"
    exec "$HOME/.local/bin/yb" tui psc --command psc --width 875 --height 600
    ```

    and is executable.
  - `defaults the title to the name and passes size and pause`: `[btop]\ncommand = "btop"\nsize = [1000, 700]\npause = true`
    → `@raycast.title btop`, no `@raycast.icon` line, ends `--width 1000 --height 700 --pause`.
  - `quotes commands with spaces`: `command = "bash -c 'dust; read -n 1 -s'"` → `--command 'bash -c '\''dust; read -n 1 -s'\'''`.
  - `removes scripts whose entry is gone`: a pre-existing `old.sh` that starts with the generated header is deleted; a file without it is kept.
  - `refuses a bad name`: `["my tui"]` → exit 1, output names the entry.
  - `--check`: exit 0 right after a build; exit 1 and output containing `tuis:build` after editing `psc.sh` or adding a stale generated file.
  - `the committed scripts are current`: `--check` against the real `config/tuis.toml` and `config/raycast/scripts/tuis` exits 0.

- [ ] **Step 2: Run it to see it fail**

  Run: `bun test test/integration/bootstrap/tuis.spec.ts` — Expected: FAIL (script missing).

- [ ] **Step 3: Implement `script/tuis-build.ts`** with `Bun.TOML.parse`, the same `quote` rule as
  `config/karabiner/src/build.ts` (`/^[\w.+-]+$/` bare, else single-quoted with `'\''`), mode `0o755`, and
  `--check` printing `stale: <path> (run mise run tuis:build)` per problem. Add `config/tuis.toml` with the `psc` entry above
  (and a header comment listing the fields: `title`, `command`, `icon`, `size`, `pause`), the `tuis:build` task
  (`run = "bun script/tuis-build.ts"`), and run `mise run tuis:build` to generate `psc.sh`.

- [ ] **Step 4: Run the spec and the linters**

  Run: `bun test test/integration/bootstrap/tuis.spec.ts && hk check --all` — Expected: pass (shellcheck/shfmt accept the generated script, taplo/tombi accept the toml).

- [ ] **Step 5: Commit**

