# hk Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make hk actually enforce Conventional Commits and run every linter correctly and fast, with a configuration that works globally across all repos and can be overridden per repo.

**Architecture:** Commit-message policy lives in `config/hk/config.pkl` (surfaced at `~/.config/hk/config.pkl`, which hk merges into every project) plus `config/cog/cog.toml` for the allowed type set. Each repo's `hk.pkl` carries only linters, and may add, override, or disable any inherited step. Hooks are generated by `hk install --mise --legacy` — no tracked wrapper scripts, no standalone shell files.

**Tech Stack:** hk 1.56.0 (Pkl config), cocogitto 7.0.0, mise, pkl 0.32.1, Bun test.

**Spec:** [design.md](design.md)

## Testing methodology note

**Validate through real `git commit`, never through `hk run commit-msg <file>`.**
Direct `hk run` invocations gave inconsistent exit codes across working
directories and staged-file states during design verification, while the real
hook was consistently correct (13/13 message shapes, including
`--allow-empty` with zero staged files). Step-level logic is covered by hk's own
`tests {}` blocks, which pass an explicit fixture and are deterministic.

**Division of labour.** Measured: `hk test` runs an assertion in ~5ms; a real
`git commit` through the hook takes ~32ms plus repo setup. So every rule that can
be expressed as "this message text produces this exit code" lives in `tests {}`
next to its step (24 cases), and the Bun spec asserts only what needs a real git:
hook wiring, Apple-git compatibility, `HK=0`, and the merge/revert/fixup/rebase
operations — plus one type and one style case to prove the config reaches the
hook.

## Task 3: Rewrite the global hk config

**Files:**
- Delete: `config/hk/hkrc.pkl`
- Create: `config/hk/config.pkl`

The current file is invalid: `pkl eval config/hk/hkrc.pkl` reports
`Cannot find property 'settings' in module 'hk.Config'`. `jobs` is top-level and
there is no `settings {}` block.

Three mechanics are load-bearing and must not be "simplified":

1. `#"""..."""#` raw strings, or Pkl reads `\(` as string interpolation.
2. `{% raw %}` / `{% endraw %}`, because hk renders commands through Tera, where
   shell's `${#var}` parses as the `{#` comment opener.
3. `{{ commit_msg_file | default(value=files) }}`, which resolves to the real
   message file under the hook and to the fixture under `hk test`.

- [ ] **Step 3: Write the real config**

Replace `config/hk/config.pkl` entirely:

```pkl
/// User-level hk configuration.
///
/// hk merges this file into every project's hk.pkl, so every repository on this
/// machine inherits the commit-message policy with no per-repo configuration.
/// A repo may add, override, or disable any step below from its own hk.pkl -
/// see config/hk/README.md.
///
/// Surfaced at ~/.config/hk/config.pkl via the ~/.config/hk directory symlink.
amends "package://github.com/jdx/hk/releases/download/v1.56.0/hk@1.56.0#/Config.pkl"

jobs = 4

// Suppress the OSC terminal-progress escape sequences.
terminal_progress = false

hooks {
  ["commit-msg"] {
    steps {
      // Conventional Commits grammar and allowed types.
      // Policy lives in cog.toml: a repo-local one wins, else the shared default.
      ["conventional-commit"] {
        check = #"""
          {% raw %}
          f="{% endraw %}{{ commit_msg_file | default(value=files) }}{% raw %}"
          subject=$(grep -v '^#' "$f" | sed -e '/./,$!d' | head -1)

          # cog.toml handles Merge and fixup!/squash!/amend! via its ignore_*
          # options. It has no revert equivalent, so guard those here.
          case "$subject" in
            Revert\ *|Reapply\ *) exit 0 ;;
          esac

          cfg="cog.toml"
          [ -f "$cfg" ] || cfg="${XDG_CONFIG_HOME:-$HOME/.config}/cog/cog.toml"
          [ -f "$cfg" ] || { echo "No cog.toml found (repo or $cfg)" >&2; exit 1; }
          exec cog --config "$cfg" --quiet verify --file "$f"
          {% endraw %}
          """#

        tests {
          ["accepts ref"] {
            write { ["c1.txt"] = "ref(nvim): Simplify keymap scheduling\n" }
            files = List("c1.txt")
            expect { code = 0 }
          }
          ["rejects refactor"] {
            write { ["c2.txt"] = "refactor(nvim): Simplify keymaps\n" }
            files = List("c2.txt")
            expect { code = 1 }
          }
          ["rejects an unlisted type"] {
            write { ["c3.txt"] = "git(config): Update the settings\n" }
            files = List("c3.txt")
            expect { code = 1 }
          }
          ["accepts a breaking marker"] {
            write { ["c4.txt"] = "feat(cli)!: Change the output format\n" }
            files = List("c4.txt")
            expect { code = 0 }
          }
          ["accepts a nested scope"] {
            write { ["c5.txt"] = "chore(core/domain): Extract constants\n" }
            files = List("c5.txt")
            expect { code = 0 }
          }
          ["rejects an unparseable message"] {
            write { ["c6.txt"] = "just some words\n" }
            files = List("c6.txt")
            expect { code = 1 }
          }
          ["skips merge commits"] {
            write { ["c7.txt"] = "Merge branch 'side' into main\n" }
            files = List("c7.txt")
            expect { code = 0 }
          }
          ["skips revert commits"] {
            write { ["c8.txt"] = "Revert \"feat(cli): Add search command\"\n" }
            files = List("c8.txt")
            expect { code = 0 }
          }
          ["skips fixup commits"] {
            write { ["c9.txt"] = "fixup! feat(cli): Add search command\n" }
            files = List("c9.txt")
            expect { code = 0 }
          }
        }
      }

      // Subject and body rules from assets/guides/GIT_COMMITS_GUIDE.md
      // that `cog verify` does not cover.
      ["commit-style"] {
        check = #"""
          {% raw %}
          f="{% endraw %}{{ commit_msg_file | default(value=files) }}{% raw %}"
          msg=$(grep -v '^#' "$f" | sed -e '/./,$!d')
          subject=$(printf '%s\n' "$msg" | head -1)

          case "$subject" in
            Merge\ *|Revert\ *|Reapply\ *|fixup!\ *|squash!\ *|amend!\ *) exit 0 ;;
          esac

          fail=0
          err() { printf '  %s\n' "$*" >&2; fail=1; }

          if [ ${#subject} -gt 50 ]; then
            err "Subject is ${#subject} chars, max 50: $subject"
          fi
          desc=${subject#*: }
          if [ ${#desc} -lt 5 ]; then
            err "Description is ${#desc} chars, min 5: $desc"
          fi
          case "$desc" in
            [A-Z]*) ;;
            *) err "Description must be capitalized: $desc" ;;
          esac
          case "$subject" in
            *.) err "Subject must not end with a period: $subject" ;;
          esac
          if printf '%s' "$subject" | grep -qiE '(^|[^a-z])wip([^a-z]|$)'; then
            err "WIP commits are not allowed: $subject"
          fi

          body=$(printf '%s\n' "$msg" | tail -n +2)
          if [ -n "$(printf '%s' "$body" | tr -d '[:space:]')" ]; then
            if [ -n "$(printf '%s\n' "$msg" | sed -n '2p')" ]; then
              err "Subject and body must be separated by a blank line"
            fi
            trailers=$(git interpret-trailers --parse <"$f" 2>/dev/null)
            fence=0
            n=1
            while IFS= read -r line; do
              n=$((n + 1))
              case "$line" in '```'*) fence=$((1 - fence)); continue ;; esac
              [ "$fence" -eq 1 ] && continue
              [ ${#line} -le 72 ] && continue
              if [ -n "$trailers" ] && printf '%s\n' "$trailers" | grep -qxF "$line"; then
                continue
              fi
              case "$line" in "BREAKING CHANGE: "*) continue ;; esac
              case "$line" in *" "*) ;; *) continue ;; esac
              err "Body line $n is ${#line} chars, max 72: $line"
            done <<EOF
          $body
          EOF
          fi

          exit $fail
          {% endraw %}
          """#

        tests {
          ["accepts a 50-char subject"] {
            write { ["t01.txt"] = "feat(cli): Add search command with FTS filters\n" }
            files = List("t01.txt")
            expect { code = 0 }
          }
          ["rejects a 51-char subject"] {
            write { ["t02.txt"] = "feat(cli): Add search command with FTS and filterss\n" }
            files = List("t02.txt")
            expect { code = 1; stderr = "max 50" }
          }
          ["rejects a lowercase description"] {
            write { ["t03.txt"] = "feat(cli): add search command\n" }
            files = List("t03.txt")
            expect { code = 1; stderr = "capitalized" }
          }
          ["rejects a trailing period"] {
            write { ["t04.txt"] = "feat(cli): Add search command.\n" }
            files = List("t04.txt")
            expect { code = 1; stderr = "period" }
          }
          ["rejects a too-short description"] {
            write { ["t05.txt"] = "feat(cli): Add\n" }
            files = List("t05.txt")
            expect { code = 1; stderr = "min 5" }
          }
          ["rejects wip"] {
            write { ["t06.txt"] = "feat(cli): WIP search\n" }
            files = List("t06.txt")
            expect { code = 1; stderr = "WIP" }
          }
          ["skips merge commits"] {
            write { ["t07.txt"] = "Merge branch 'feature/x' into main with a long tail\n" }
            files = List("t07.txt")
            expect { code = 0 }
          }
          ["skips revert commits"] {
            write { ["t08.txt"] = "Revert \"feat(cli): Add search command\"\n" }
            files = List("t08.txt")
            expect { code = 0 }
          }
          ["skips fixup commits"] {
            write { ["t09.txt"] = "fixup! feat(cli): Add search command\n" }
            files = List("t09.txt")
            expect { code = 0 }
          }
          ["accepts a wrapped body"] {
            write {
              ["t10.txt"] = """
                feat(cli): Add search command with filters

                Enable fast full-text search across all entry types using
                SQLite FTS5, supporting type and tag filter combinations.

                """
            }
            files = List("t10.txt")
            expect { code = 0 }
          }
          ["rejects an over-long body line"] {
            write {
              ["t11.txt"] = """
                feat(cli): Add search command with filters

                xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx and more

                """
            }
            files = List("t11.txt")
            expect { code = 1; stderr = "max 72" }
          }
          ["rejects a missing blank line"] {
            write {
              ["t12.txt"] = """
                feat(cli): Add search command with filters
                Body immediately after subject with no separator.

                """
            }
            files = List("t12.txt")
            expect { code = 1; stderr = "blank line" }
          }
          ["exempts long trailers"] {
            write {
              ["t13.txt"] = """
                feat(cli): Add search command with filters

                Enable fast full-text search.

                Reference: https://www.sqlite.org/fts5.html#the_highlight_function_and_more
                Co-authored-by: Somebody With A Rather Long Name <somebody@example.com>

                """
            }
            files = List("t13.txt")
            expect { code = 0 }
          }
          ["exempts BREAKING CHANGE"] {
            write {

                Switch the default renderer.

                BREAKING CHANGE: scripts relying on default table output must now pass --format table

                https://www.example.com/a/very/long/url/that/cannot/be/wrapped/at/all/ever/okay

                """
            }
            files = List("t15.txt")
            expect { code = 0 }
          }
        }
      }
    }
  }
}

## Task 4: Wire the global config and install hooks

**Files:**
- Modify: `mise.toml` (`setup:hooks`, currently lines 259-271)
- Modify: `install` (`prepare_tools_hk`, currently lines 706-726)

`hk install`'s default writes config-based hooks (`hook.<name>.command`), which
Apple's `/usr/bin/git` 2.50.1 silently ignores — commits pass unvalidated with no
warning. `--legacy` writes `.git/hooks/` shims that every git version runs, and
`--mise` wraps them in `mise x` so hk resolves without mise activation.

- [ ] **Step 1: Replace the `setup:hooks` task**

```toml
[tasks."setup:hooks"]
description = "Link the global hk/cog config and install this repo's git hooks"
run = '''
#!/usr/bin/env bash
set -euo pipefail
DOTS="${DOTS_DIR:-$HOME/.local/share/dots}"
CFG="${XDG_CONFIG_HOME:-$HOME/.config}"

# hk reads ~/.config/hk/config.pkl and cog reads ~/.config/cog/cog.toml.
# Link the directories so edits in the repo take effect immediately.
for d in hk cog; do
  if [ ! -e "$CFG/$d" ]; then
    ln -snf "$DOTS/config/$d" "$CFG/$d"
    echo "linked $CFG/$d -> $DOTS/config/$d"
  fi
done

# --legacy: script shims run on every git version. Apple's /usr/bin/git (2.50.1)
#           silently ignores config-based hooks, so the default is unsafe here.
# --mise:   hooks resolve hk through `mise x`, so mise need not be activated.
hk install --mise --legacy --force-local

# Quiet on success; a failing step still prints its full diagnostics.
hooks_dir="$(git rev-parse --git-path hooks)"
for h in "$hooks_dir"/*; do
  case "$h" in *.sample) continue ;; esac
  [ -f "$h" ] || continue
  sd '(hk run [a-z-]+)( --from-hook)' '$1 -q$2' "$h"
done
echo "hk hooks installed for $(git rev-parse --show-toplevel)"
'''
```

- [ ] **Step 2: Fix the broken symlink call in `install`**

In `prepare_tools_hk`, replace:

```sh
  # Symlink config.pkl to hkrc.pkl in ~/.config/hk/
  ensure_dir "$HOME/.config/hk"
  backup "$HOME/.config/hk/config.pkl" "hkrc.pkl"
```

with:

```sh
  # hk reads ~/.config/hk/config.pkl and cog reads ~/.config/cog/cog.toml.
  # Link the directories; the repo already names the files correctly.
  for hk_cfg_dir in hk cog; do
    backup "$HOME/.config/$hk_cfg_dir" "$HOME/.local/share/dots/config/$hk_cfg_dir"
  done
```

The old call passed the **relative** path `hkrc.pkl` as the symlink source.
`backup()` guards with `[ -e "$source" ]`, which was never true from the install
working directory, so `ln -sf` never ran. That is why `~/.config/hk` did not
exist and the distributed defaults were never active.

import { afterAll, beforeAll, describe, expect, it } from "bun:test";
import { mkdtempSync, rmSync, writeFileSync } from "node:fs";
import { join } from "node:path";
import { tmpdir } from "node:os";

// Apple's /usr/bin/git is older than 2.54 and silently ignores config-based
// hooks. Every commit here goes through it deliberately: it is what VS Code and
// GUI clients get, and what the legacy shims must survive.
const APPLE_GIT = "/usr/bin/git";
const CLEAN_PATH = "/usr/bin:/bin:/usr/sbin:/sbin:/opt/homebrew/bin";

let repo: string;

function git(args: string[], env: Record<string, string> = {}) {
  return Bun.spawnSync([APPLE_GIT, ...args], {
    cwd: repo,
    stdout: "pipe",
    stderr: "pipe",
    env: { ...Bun.env, PATH: CLEAN_PATH, ...env },
  });
}

function commit(message: string, env: Record<string, string> = {}) {
  return git(["commit", "--allow-empty", "-m", message], env);
}

function stderrOf(r: { stderr: Uint8Array }) {
  return new TextDecoder().decode(r.stderr);
}

beforeAll(() => {
  repo = mkdtempSync(join(tmpdir(), "hk-hooks-"));
  for (const args of [
    ["init", "-q", "-b", "main", "."],
    ["config", "user.email", "test@example.com"],
    ["config", "user.name", "Test"],
    ["config", "commit.gpgsign", "false"],
  ]) {
    git(args);
  }
  writeFileSync(
    join(repo, "hk.pkl"),
    'amends "package://github.com/jdx/hk/releases/download/v1.56.0/hk@1.56.0#/Config.pkl"\n',
  );
  writeFileSync(join(repo, "mise.toml"), '[tools]\nhk = "1.56.0"\ncocogitto = "7.0.0"\n');
  const install = Bun.spawnSync(["hk", "install", "--mise", "--legacy", "--force-local"], {
    cwd: repo,
    stdout: "pipe",
    stderr: "pipe",
  });
  expect(install.exitCode).toBe(0);
  git(["add", "-A"]);
  expect(commit("feat(hk): Add initial configuration").exitCode).toBe(0);
});

afterAll(() => rmSync(repo, { recursive: true, force: true }));

describe("hk git hooks", () => {
  describe("wiring", () => {
    it("installs a script shim rather than a config-based hook", () => {
      expect(Bun.file(join(repo, ".git/hooks/commit-msg")).size).toBeGreaterThan(0);
      expect(git(["config", "--get-regexp", "^hook\\."]).exitCode).not.toBe(0);
    });

    it("enforces rules under Apple git with hk absent from PATH", () => {
      const which = Bun.spawnSync(["sh", "-c", "command -v hk"], {
        env: { PATH: CLEAN_PATH },
        stdout: "pipe",
      });
      expect(which.exitCode).not.toBe(0);
      expect(commit("feat(cli): add lowercase").exitCode).not.toBe(0);
    });

    it("bypasses every hook when HK=0", () => {
      expect(commit("totally invalid message", { HK: "0" }).exitCode).toBe(0);
      git(["reset", "--hard", "HEAD~1"]);
    });
  });

  // Type and subject-style rules are covered exhaustively by `hk test` in
  // config/hk/config.pkl, which is ~7x faster per assertion. Only one of each
  // is asserted here, to prove the config is actually reaching the hook.
  describe("policy reaches the hook", () => {
    it("rejects refactor, proving the shared cog.toml is in effect", () => {
      expect(commit("refactor(nvim): Simplify keymaps").exitCode).not.toBe(0);
    });

    it("rejects an uncapitalized description", () => {
      expect(stderrOf(commit("feat(cli): add search command"))).toContain("capitalized");
    });
  });

  describe("machine-generated commits are exempt", () => {
    it("allows git merge --no-ff", () => {
      git(["checkout", "-q", "-b", "side"]);
      expect(commit("feat(b): Add side work").exitCode).toBe(0);
      git(["checkout", "-q", "main"]);
      expect(commit("feat(c): Add main work").exitCode).toBe(0);
      expect(git(["merge", "--no-ff", "-m", "Merge branch 'side'", "side"]).exitCode).toBe(0);
    });

    it("allows git revert of a normal commit", () => {
      writeFileSync(join(repo, "r.txt"), "x\n");
      git(["add", "-A"]);
      expect(git(["commit", "-m", "feat(r): Add a file to revert"]).exitCode).toBe(0);
      expect(git(["revert", "--no-edit", "HEAD"]).exitCode).toBe(0);
    });

    it("allows git commit --fixup", () => {
      writeFileSync(join(repo, "fx.txt"), "x\n");
      git(["add", "-A"]);
      expect(git(["commit", "--fixup", "HEAD"]).exitCode).toBe(0);
    });

    it("allows rebase --autosquash", () => {
      const r = git(["rebase", "--autosquash", "-i", "HEAD~2"], {
        GIT_SEQUENCE_EDITOR: "true",
      });
      expect(r.exitCode).toBe(0);
    });
  });
});

- [ ] **Step 1: Replace the README**

```markdown
# hk Configuration

User-level configuration for [hk](https://hk.jdx.dev), the Rust-native git hook
manager, plus the shared [cocogitto](https://docs.cocogitto.io) commit policy.

## Files

- `config.pkl` - global hk config. hk **merges** it into every project's
  `hk.pkl`, so every repository inherits the commit-message rules with no
  per-repo configuration.
- `../cog/cog.toml` - the allowed Conventional Commits type set.

Both are surfaced through directory symlinks created by `mise run setup:hooks`:

    ~/.config/hk  -> ~/.local/share/dots/config/hk
    ~/.config/cog -> ~/.local/share/dots/config/cog

Because `~/.local/share/dots` points at the working copy, editing these files
changes the live configuration immediately - there is nothing to re-install.

## Installing hooks in a repository

    mise run setup:hooks                        # in dots
    hk install --mise --legacy --force-local    # in any other repo

`--legacy` is **required**. Without it hk writes config-based hooks
(`hook.<name>.command`), which git older than 2.54 - including Apple's
`/usr/bin/git` - ignores silently, so commits go unvalidated with no warning.
`--mise` makes hooks resolve hk through `mise x`, so mise need not be activated
in the shell that runs git.

## Per-repo customization

A repo customizes inherited rules from its own `hk.pkl`. The merge is
**per-property**, so an override only names what it changes.

| Intent | How |
| --- | --- |
| Add a rule | Declare a new step under `["commit-msg"]` |
| Override a rule | Redeclare the step **by the same name**, setting only what changes |
| Disable a rule | Redeclare by name with `step_condition = "false"` |
| Disable conditionally | Redeclare by name with `profiles = List("some-profile")` |

    // Relax the subject limit in one repository
    hooks {
      ["commit-msg"] {
        steps {
          ["commit-style"] { step_condition = "false" }
        }
      }
    }

For commit **types**, drop a `cog.toml` in the repo root - it takes precedence
over the shared one, so a repo can add types without losing the baseline.

## Self-contained repos

Repos shared with people who do not use these dotfiles should copy the two
`commit-msg` steps from `config.pkl` into their own `hk.pkl` and commit their own
`cog.toml`. The step definitions are identical in both modes; only their location
differs.

## Editing `config.pkl`

Three mechanics are load-bearing:

1. **`#"""..."""#` raw strings.** Plain `"""..."""` makes Pkl read `\(` as string
   interpolation, which is invalid. hk's embedded evaluator (`pklr`) tolerates
   it; the `pkl` CLI and `pkl-lsp` do not.
2. **`{% raw %}` / `{% endraw %}`.** hk renders commands through Tera, where
   shell's `${#var}` parses as the `{#` comment opener. hk's own `{{...}}`
   variables go outside the raw block.
3. **`{{ commit_msg_file | default(value=files) }}`.** Resolves to the message
   file under the hook and to the fixture under `hk test`, so one definition is
   both correct and testable.

Always run both after editing:

    pkl eval config/hk/config.pkl   # must render the config, not an error
    hk test --cd config/hk          # must be all `ok`

## Commands and environment

- `hk check` / `hk fix` - lint, with or without applying fixes
- `hk test` - run the step tests defined in the config
- `hk validate` - validate the config
- `HK=0 git commit ...` - bypass all hooks
- `HK_SKIP_STEPS=shfmt git commit ...` - skip one step
- `HK_SKIP_HOOK=pre-commit git commit ...` - skip one hook

The full list is at <https://hk.jdx.dev/environment_variables.html>.
```
